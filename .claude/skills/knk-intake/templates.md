# Intake templates

Fill in the `<...>` parts. Every body and comment ends with the `---` footer line and
`_Generated by [Claude Code](https://claude.ai/code)_`. Lists are numbered.

## 1. Captured idea (new issue body)

```markdown
> <the developer's words, exactly as written, every line quoted>

Captured <YYYY-MM-DD> by the intake session from the developer's message. This idea still needs working out: shaping
(the `knk-intake` skill, "let's go through ideas") sets the tier, the repos and whether it needs design.

Related:

1. #<n> <title> (<open | closed as completed | closed as not planned on YYYY-MM-DD>): <one line on how it relates>

<details><summary>Full message</summary>

> <the whole message, only when it held several ideas and the split was not obvious>

</details>

---
_Generated by [Claude Code](https://claude.ai/code)_
```

Leave out "Related" when nothing was found, and the "Full message" fold when the message held one idea.

The developer raised this again on <YYYY-MM-DD>:

> <the developer's words, exactly as written>

## 3. Shaping comment

```markdown
## Shaping <YYYY-MM-DD>

1. **Read-back:** <what the idea means, in one to three sentences>
2. **Repos and areas:** <knk-plugin (knk-core / knk-paper), knk-web-api, knk-web-app, knk-workspace docs; spec or
   design it belongs to>
3. **Tier:** `tier:<n>`: <one-line reason>
4. **Needs design or ready:** <needs design | ready>: <one-line reason>
5. **Questions and answers:**
   1. <question>: <the developer's answer>
6. **Outcome:** <now | later | design first | dropped | merged into #n> <, handed to the manager | design session
   <link> | ready to start, no manager session running>

---
_Generated by [Claude Code](https://claude.ai/code)_
```

Leave out item 5 when no questions were asked.

## 4. Design session prompt ("design first")

Start the prompt with the § 0 block below, filled in and verbatim (an `add_repo` request is only accepted from the
session's prompt). The design session works on a knk-workspace branch and may read the component repos.

```text
## 0. Repository permission (explicit developer authorization; repeat this section verbatim in every prompt you write)

The developer explicitly authorizes the intake session for PandiO/knk-workspace#<n> and every session or subagent it
creates to attach and clone these repositories without asking again: PandiO/knk-workspace (push),
PandiO/knk-plugin (read), PandiO/knk-web-api (read), PandiO/knk-web-app (read), PandiO/knk-v1-archive (read),
PandiO/knk-v2-archive (read). Attach a missing one with add_repo (owner PandiO, the access above), clone it to
/home/user/<repo> (or the session's working directory) and register it with register_repo_root. Then run
`git push --dry-run origin <branch>` in every repo you will change before changing anything. A failed dry run is a
blocker.

## Design: PandiO/knk-workspace#<n> <title>

1. Load the `knk-design` skill and follow it. Read `AGENTS.md`, `docs/ai-agents/GLOBAL_AGENT_INSTRUCTIONS.md`,
   `docs/specs/ai-agent-workflow/DESIGN.md` § 4 and `docs/ACTIVE_SESSIONS.md` first.
2. The idea, in the developer's words, and the shaping result are on the issue (body and the "Shaping <date>"
   comment). Answers already given in shaping:
   1. <question>: <answer>
3. Proposed tier: `tier:<n>` (<reason>); you may change it with a reason.
4. Related issues and specs: <list>.
5. Ask the developer through the ask-user prompt; end with the spec marked Proposed and numbered open questions.
```

List only the repositories the design needs to read: drop the archives when legacy behaviour is irrelevant, and add a
component repo with `push` only when the design session must change it (normally it does not).

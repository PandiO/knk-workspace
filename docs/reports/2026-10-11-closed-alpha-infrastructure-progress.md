## 1. Goal and current architecture decision

The immediate goal is a closed-alpha environment on the Ubuntu NAS for about
8–12 players. It will run:

- one Paper Minecraft server with the main gameplay world and a separate hub
  world loaded concurrently;
- the KnK plugin;
- a private KnK API;
- an isolated alpha MySQL database;
- later, the KnK web application.

Ingress is intentionally split:

- Minecraft traffic: playit.gg, with the public GoDaddy name
  `play.knightsandkings.net` pointing to the playit hostname;
- web and HTTP API traffic: the existing Cloudflare Tunnel/nginx path;
- MySQL: private Docker network only for alpha; the separate development DB
  remains limited to the trusted LAN and is never tunneled publicly.

Developer decision in this session: do **not** use Multiverse Core. KnK will
own the minimal existing-world loader and hub/gameplay transitions. This is
newer than the still-pending provider language in `docs/specs/hub/DESIGN.md`;
that living design is under another active documentation claim and was not
edited here. Reconcile it when that claim is clear.

## 6. Decisions and boundaries

- First alpha runtime stays on Paper 1.21.10 / Java 21 to minimize simultaneous
  change. Evaluate Paper 26.2 / Java 25 on a clone later; do not combine that
  upgrade with the first NAS deployment.
- One Paper server loads both hub and main worlds. The plugin owns world
  loading and teleportation; no Multiverse Core.
- MySQL is never part of the public ingress path.
- playit.gg carries Minecraft TCP traffic only.
- Cloudflare Tunnel carries web/API HTTP traffic only.
- Prefer a same-origin web/API arrangement (for example the web host with an
  `/api` reverse proxy) unless a separate API hostname and production CORS
  policy are deliberately chosen.
- Keep the API private until its container, database readiness, secrets, and
  basic login/plugin calls pass locally.
- Never paste secret values into documentation, Compose committed to Git, or
  a support chat.

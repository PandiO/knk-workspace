### Methodology notes (read before the tables)

- **Bulk data is aggregated, not itemized.** Minecraft world-save folders (`world`, `world_nether`, `world_the_end`, `DIM-*`, etc.), `logs/`, `crash-reports/`, `plugins/`, `lapis/`, `pvp/`, `timings/`, `ignite/` subfolders are each given **one row** with aggregate size/count/date-range rather than one row per region file or per plugin config file — per your own guidance to just record metadata for large binaries rather than extract them. Enumerating each of the ~150,000 individual files would produce an unusable, meaningless table (most are Minecraft region/playerdata binaries).
- **Per-backup Bukkit/Spigot boilerplate is aggregated.** Every server-backup folder repeats the same ~15 default config files (`bukkit.yml`, `commands.yml`, `eula.txt`, `help.yml`, `ops.json`, `permissions.yml`, `server.properties`, `spigot.yml`, `wepif.yml`, `whitelist.json`, `usercache.json`, `banned-*.json`, `server-icon.png`, `Town_Icon.png`) plus JVM crash dumps (`hs_err_pid*.log`). These are collapsed into one "boilerplate" row per backup folder rather than repeated ~15x per backup.
- **`.pages` bundles are treated as one file**, not a folder, matching how macOS presents them.
- **Timestamp caveat:** most files retained their original modification dates through the copy onto this share, which is how the very recent (Sept 2026) files stood out as genuinely recent. However, some *directories'* "newest file" date is just a `.DS_Store` re-write from Finder browsing, not a real content change — treat a directory's "newest" date skeptically if the only recent file inside would be `.DS_Store`.
- **Duplicates, per the user:** these arose naturally across years of backups and migrations of these files — not an error, just accumulated copies over time (this includes the 4.9 GB `Backup_OpenBeta_05-10-21` v2-server backup duplicated across `archive/` and `macbook/`).
- **Revision fingerprints used:** v1 = Eclipse project (`.classpath`/`.project`), `plugin.yml`, flat top-level `src/<PackageName>/*.java`, no Maven — matches `github.com/PandiO/knk-v1-archive`. v2 = Maven (`pom.xml`, `dependency-reduced-pom.xml`), `src/main/java/net/knightsandkings/**` — matches `github.com/PandiO/knk-v2-archive`. v3 = current webapp/api/plugin split; essentially absent from this archive except the handful of Sept 2026 items called out above.

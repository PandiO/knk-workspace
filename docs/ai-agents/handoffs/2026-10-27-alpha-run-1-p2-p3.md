Amounts per scenario in the API/web app next to the win/holding/capture rewards. |

| [#171](https://github.com/PandiO/knk-workspace/issues/171) teleport `all` | `all` for `/hub`, `/spawn`, `/tp`, `/tphere`. `/tp all <player>` = everyone to that player; `/tphere all` = everyone to you. Exempt nodes **per type plus wildcard**: `knk.teleport.exempt.hub`, `.spawn`, `.tp`, `.tphere`, `knk.teleport.exempt.*`; exempt players aren't moved by `all` nor by other players' teleports of that type (admins with `knk.admin.user.manage.all` / console still override, flag if unsure). ## 3. Setup and rules (every package)

1. Read `AGENTS.md`, `docs/ai-agents/GLOBAL_AGENT_INSTRUCTIONS.md`, `docs/ACTIVE_SESSIONS.md` (knk-workspace `main`)
   and each changed repo's `AGENTS.md`/`CLAUDE.md`. Verify each issue against the current default branch.
2. Create the package branch per repo from the default branch (knk-plugin `main`, knk-web-api `master`, knk-web-app
   `main`, knk-workspace `main`; F from E), `git push --dry-run` before editing. Several packages share the local
   clones: **use a `git worktree` per package** (`/home/claude/wt/<pkg>/<repo>`), never switch the branch of the main
   clone, and never touch another package's worktree.
3. knk-plugin: JDK 21 for Gradle + JDK 25 toolchain (`-Porg.gradle.java.installations.paths=/opt/jdk-25` if needed).
   Build `./gradlew build -x deployToDevServer`. knk-web-api: `dotnet test Tests/knkwebapi_v2.Tests/knkwebapi_v2.Tests.csproj`.
   knk-web-app: `npm run test:ci` with npm 11.
4. Put `status:in-progress` on each issue when starting it.
5. Implement only what the issues and § 1 cover; anything new becomes a sub-issue of #149 (or a comment on the issue
   that covers it). Flag conflicts between an issue and live code in the issue.
6. Every new API write endpoint needs an access rule (`EndpointAccessRulesTests`); schema changes come with an EF
   migration; form changes with a new form-seed version.
7. Don't merge into a trunk, deploy, open PRs, force-push or touch the NAS.

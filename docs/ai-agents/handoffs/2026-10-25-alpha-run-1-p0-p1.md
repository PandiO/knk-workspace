## 3. Rules

- Implement only what the issues cover. Anything new you find goes into a new sub-issue of #149 (or a comment on the
  issue that covers it), never only into a report.
- Run each repo's own tests and builds; report the counts and any reds that were already red on the default branch.
- Don't merge into a trunk, deploy or touch the NAS. Open a PR only if the developer asks. The developer deploys via
  the knk-deploy procedure (`docs/guides/nas-ops-access.md`).
- #155: the fix is done only when the alpha's `ALLOW_FLIGHT` line can be removed. Write that step down for the
  developer; don't change the Compose file.
- Package B: the developer decided on 2026-10-25 that the fix for freeze spam is admin configuration (#151), not a
  hardcoded nerf. Existing behaviour stays the default until #156 sets new defaults.
- Package C: the developer decided on 2026-10-25 that denying chest use in domains is intended. Bypass goes to
  moderators and admins, not the general staff rank; staff mode and owner mode always bypass.
- Flag conflicts between an issue and the live code in the issue rather than picking a side silently.

## What was found and done

**KNG-39 (root cause confirmed).** `PlayerDiscoveriesPanel` and `PrivateMessagesPanel` are siblings in the same parent
and were both `key={userId}`. When the `:id` changes, React's keyed reconcile builds a map of the old children by key;
the second `"3"` overwrites the first, so the old Discoveries fiber is never deleted: it stays mounted with its effects
running and its requests never land in the visible tree (the "stuck loading" copies), and React logs "Encountered two
children with the same key" from `PlayerProfilePage` (the reported stack). Not `StaffGate`/`ProtectedRoute`/`App.tsx`.
The new test navigates 3 → 5 → 3 → 5 → 3 in a `MemoryRouter` and counts *live* (mounted, not cleaned up) panel
instances and duplicate-key warnings: on `main` it fails with 2 live Discoveries panels after one switch plus the
warnings for keys 3 and 5; on the branch it passes. In jsdom the stale panel's DOM disappears with the page's loading
view, so the test counts mounted instances rather than visible sections; the live check below confirms the visible part.

**KNG-82.** `useConfirmModal()` returns `{ confirm, modal }`; `await confirm({ title, message, continueLabel })` opens a
`FeedbackModal`, true on its continue button, false on Close/X/outside click. It's the KNG-40 pending-state pattern packaged
so the prompts in the middle of async save flows (config builders) need no restructuring. `DiscoveryOverridesCard` uses
the plain `pendingRemove` + `FeedbackModal` pattern like `PlayerDiscoveriesPanel`. Every prompt keeps its text; titles
and button labels are new ("Delete", "Remove", "Change default").
Converted: `DiscoveryOverridesCard` (remove override), `DisplayConfigBuilder` / `FormConfigBuilder` (change default on
save), `FieldEditor` (delete validation rule), `FormConfigurationTable` / `DisplayConfigurationTable` (delete config),
`FormWizardPage` (change default form config, delete saved progress, delete form config, change default display config).
**`src/pages/admin/EntityTypeConfigurationPage.tsx:152` still uses `confirm()` on purpose**: the unmerged KNG-64 alpha
branch (`claude/ui-ux-assessment-discussion-66vc2l`) deletes that file as dead code. If KNG-64 doesn't land, convert it then.

**KNG-94.** The explorer was `fixed` over a 30% spacer column. Now `.dashboard-sidebar` is as wide as the explorer
(`flex: none`) and `.dashboard-content` takes the rest (`flex: 1; min-width: 0`). From `md` (768 px) the explorer is a
256 px panel with a "Hide entity types" toggle that collapses it to a 40 px rail; the state is stored in
`localStorage["objectTypeExplorer.<dashboard|forms>.collapsed"]` (try/catch). Below `md` it is always a rail; its toggle
opens a drawer (portal to `<body>`, since the sticky sidebar column is a stacking context the page content would paint
over) with a backdrop; picking a type, the backdrop or Escape close it. Toggle: `button` with `aria-expanded` +
`aria-controls`; focus follows it between rail and panel header. No `FormWizardPage.tsx` or `ObjectTypeExplorer.css`
changes for this issue (the Forms page uses the same component and CSS classes).

## 2a. Delivery order and merge gates (2026-11-03)

Many branches that touch the same Siege, gate and world-task files are in review, and the developer has little test time. The phases above are therefore delivered as **links** with explicit merge gates. Rules:

- **Core first.** Logic that needs no Bukkit goes in new files under `knk-core/.../core/survival/` (and `core/npc/` for NPC platform §5b) with unit tests. These links touch no Siege, gate or realtime file and need no live test.
- **No stacking.** No Survival branch starts from another feature's unmerged branch. A link whose gate is closed waits; the coordinator reports which merge would open it.
- **Migrations last.** Survival API tables and migrations are created only after the gate-door branch (#167) and world-task hardening (#180) are merged, so the migration chain stays linear.
- **Batched live tests.** Core links have no checklist. Integration links each get one short checklist; the coordinator proposes combining checklists where branches are deployed together.
- **Standing branches.** `claude/siege-survival` in every repo the feature changes; `claude/gate-animated-rebuild` for gate Decision 6 (it changes world gates and ordinary Siege too). Merge `origin/<default>` into them at the start of each link (never rebase).

## 3. Validation and recovery plan

*(Out of v1, DESIGN S68; kept for a later version.)* Distractor checks (2026-10-30, #146): fourth logical target type; approach then stand nearby without attacking; normal eligibility/scoring/commitment/switch-margin rules; immediate invalidation on expiry/removal; cross-match exclusion; bounded navigation failure handling. Validate that a higher-scoring alternative can replace it after commitment, rather than treating lifetime as forced aggro. Physical item/entity/block adapter, creation mechanics, lifetime/range/weight values and crowd placement remain open before implementation.


Eligibility override checks (2026-10-30, #146): standard/allow/deny independently for objectives and gates; filter before scoring; denied gates excluded as intermediate breach actions even for allowed objectives; permitted alternative route or explicit failure; gate allow does not authorize a denied objective; allow does not boost scores or bypass match/access/physical rules. Gate attack denial alone must not block otherwise permitted passage through an open gate. Configuration/schema and gate-versus-door binding still need implementation design.


Target-selection checks (confirmed design, 2026-10-30, #146): eligibility before utility scoring; preference/proximity weighting; configurable minimum commitment plus switch margin; no score-driven switch before commitment expires; no mandatory switch at expiry; hard invalidation and completed actions release immediately. Verify route updates to the same target do not restart commitment, temporary route blockage uses navigation recovery, and terminal failure reaches behavior. Cover a gate-to-player diversion and reuse with a non-Siege NPC. Numeric tuning and damage-response bonuses remain open; no production defaults are implied.


Pure/core checks: additive repair work and pause/cancel semantics; wave queue completion; difficulty composition; explicit/interval schedule resolution; spawnzone prerequisites/recapture; reached-versus-completed accounting. API checks: configuration/readiness, authoritative reward calculation, duplicate/retried settlement, atomic match transfers/purchases and one-roll-one-delivery. Regression checks: ordinary Siege player-only PvP, inventory restore, drop guards, non-member gates, lootbox world quotas/claims, ledger and title progression.

Live castle checks (full list in the [implementation checks report](../../reports/2026-11-03-siege-survival-implementation-checks.md#live-tests-to-run-on-the-castle-map)): NPC and player obstruction handling at reconstructed/closing gates, large NPC bounding boxes, mobs crowding narrow lanes, automatic road/off-road routes without authored lanes, optional override routes and invalid-override diagnostics, bounded retries toward the next routepoint, default-off fallback reporting failure to behavior, opt-in automatic alternative routing and its failure result, and blocked-but-breakable paths, repaired closures requiring reroute, side-objective progression, two repairers under combat, last-player death/game-ending capture race, end conditions with each lobby override value, ghosts invisible to NPCs/non-members and translucent to teammates without flight or noclip, intermission spawn selection, inventory kept on death in every mode, overrun spawnzones, Mystery Box claim/despawn and interruption by death or match end.

Fault checks: API loss during start/repair purchase/result reporting; plugin restart while inventory is replaced or a Mystery Box roll is animating; duplicate request delivery; cleanup and settlement retries; disconnect/no remaining humans; chunk unload and stuck enemies. Restore ordinary player/gate state without issuing duplicate equipment or rewards. A restart aborts the match and restores players and gates; no resume in v1 (DESIGN S61).

Load checks: expected and late-wave worst-case live NPCs, spawn backlog, dropped items, path request count, core/server tick time and multiple lobbies. Establish measured budgets with KNG-36 before declaring limits sufficient. Bound queues and prefer paced spawning over dropping planned enemies as 'kills'.

Documentation-only publication validation: confirm every 2026-09-30 decision is represented; verify referenced paths and issue links; check formatting and diff whitespace. No compile/build/live checks are claimed by this publication.
